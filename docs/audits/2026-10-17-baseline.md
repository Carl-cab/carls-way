## The gap this audit found

`app/api/migrate/route.ts` is the only mechanism by which the production schema
changes. Its SQL was executed **nowhere** in the suite:

- `lib/__tests__/migrate-route-anonymous-path.test.ts` mocks `@/lib/db`
  wholesale — deliberately, since it tests the handler's control flow.
- `lib/__tests__/schema-source-parity.test.ts` parses the file with regular
  expressions.
- `lib/__tests__/correlation-id-schema.test.ts` runs `initializeSchema()`, not
  the route.

So roughly 66 `ALTER` and 17 `CREATE TABLE` statements that production depends
on had no execution coverage. Demonstrated rather than asserted: one statement
was changed to `ADD COLUM` — a plausible typo, and valid TypeScript — and

```
pnpm run typecheck → clean
pnpm test          → 735 passed
```

The failure would have surfaced only when an operator ran `/api/migrate`
against production. CLAUDE.md already records five separate incidents centred
on this one file.

## Standing limits, carried forward

- `AdminAuditService.verifyImmutability()` returns a hardcoded `'clean'` with
  `total_logs_checked: 0`. Nothing calls it.
- The parity test type-checks only `ALTER`-added columns, not columns declared
  inside a `CREATE TABLE` body.
- `ADD COLUMN IF NOT EXISTS` cannot alter an existing column's type, so no
  schema source can correct a width or precision mismatch; that needs a
  dedicated migration.
